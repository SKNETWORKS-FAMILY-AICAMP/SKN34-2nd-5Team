# yelp_data 전체 초기 적재 계약

## 목적

`database/load/load_yelp_data.py`는 비어 있는 `yelp_data`를 운영 서비스와
Trust Center에 필요한 전체 데이터로 한 번에 구성하는 기본 진입점이다.
v04만 적재하고 v02·v03 비교 자료나 운영 기준정보를 누락한 DB를 정상 완료로
처리하지 않는다.

## 적재 범위

1. v04 운영 데이터
   - 코호트와 Core 43개 피처
   - 검증 결과와 최종 Test 예측
   - 다중분류 평가 지표와 피처 중요도
   - 리뷰어 권역과 월별 활동
2. v03 Trust Center 비교 자료
   - 다중분류 평가 지표와 피처 중요도
3. v02 Trust Center 비교 자료
   - 이진분류 평가 지표와 피처 중요도
4. 리텐션 운영 기준정보
   - 플레이북 4개
   - 위험 유형별 세부 전략 6개

`operator_decisions`는 향후 운영 입력을 저장할 빈 테이블이며 초기 데이터 적재
대상이 아니다. 공간 피처 실험 산출물은 최종 Core 43개 모델과 현재 DB 계약에
포함되지 않으므로 이 로더가 적재하지 않는다.

## 실행 전 조건

- `database/ddl/000_create_database.sql`로 `yelp_data` DB가 생성되어 있어야 한다.
- `.env` 또는 `DATABASE_URL`이 `yelp_data`를 가리켜야 한다.
- 전체 적재 관리 대상 테이블은 비어 있어야 한다.
- v04 데이터·모델 산출물과 v02·v03 리포트 원본이 표준 경로에 있어야 한다.

로더는 기존 행을 자동 삭제하거나 덮어쓰지 않는다. 기존의 불완전한 개발용
`yelp_data`를 다시 구성할 때는 사용자가 대상 DB를 확인하고 수동 초기화한 뒤
실행한다.

## 실행

먼저 DB 변경 없이 전체 원본 계약과 예상 행 수를 검증한다.

```bat
python database\load\load_yelp_data.py --dry-run
```

검증 후 전체 적재를 실행한다.

```bat
python database\load\load_yelp_data.py ^
  --confirm-database yelp_data
```

## 누락 방지

- DB 연결 전에 v04·v03·v02·플레이북 원본 계약을 모두 검증한다.
- 실제 연결 DB와 확인값이 모두 `yelp_data`인지 검사한다.
- 기존 관리 대상 데이터가 한 행이라도 있으면 스키마 적용 전에 중단한다.
- 스키마 적용 후에도 관리 대상 테이블이 비어 있는지 다시 확인한다.
- 모든 데이터 적재와 적재 후 검증을 하나의 데이터 트랜잭션으로 실행한다.
- 적재 후 모든 테이블을 `model_version`별 예상 행 수와 대조한다.
- `model_versions`가 v02·v03·v04 각 1행인지 확인한다.
- 플레이북 4행, 위험 유형별 세부 전략 6행, 운영 판단 0행을 확인한다.
- 한 항목이라도 다르면 데이터 트랜잭션 전체를 롤백하고 실패로 종료한다.

MySQL DDL은 트랜잭션 롤백 대상이 아니므로 적재 실패 후 빈 테이블이 남을 수
있다. 데이터 행은 하나의 InnoDB 트랜잭션으로 처리되며 부분 적재를 완료로
간주하지 않는다.
