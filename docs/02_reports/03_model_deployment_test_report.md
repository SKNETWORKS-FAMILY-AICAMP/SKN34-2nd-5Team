| 항목 | 내용 |

## 2. 검증 범위

### 2.1 포함 범위

- React 정적 품질 검사와 프로덕션 빌드
- Python 모듈 컴파일 및 배포 워크플로에 포함된 자동 테스트
- v05 운영 컨텍스트·UI·모델 로더 계약 테스트
- 운영 서비스 접속, 상태 확인, 최종 모델 표시 확인
- 쓰기 작업이 필요하지 않은 기존 실패 항목의 선택 재검증
- 요구사항 6.2 배포 게이트 충족 여부 판정

### 2.2 제외 범위

- 데이터 전처리 결과서, 모델 학습 결과서 및 최종 모델 산출물 생성·정리
- 운영 DB를 변경하는 snooze 저장·복원 및 운영안 생성 테스트
- 별도 계정이 필요한 OPERATOR·VIEWER 권한 회귀
- 기존 QA 135건 전체 재실행

제외 항목은 미통과로 간주한 것이 아니라 이번 검증에서 재실행하지 않은 항목이다. 기존 결함은 수정 및 재검증 근거가 확인될 때까지 해소된 것으로 처리하지 않는다.

### 4.1 인증 테스트 실패

실패 항목은 `auth_service/tests/test_auth_flow.py::test_pending_user_can_be_refreshed_approved_and_logged_in`이다. 테스트 fixture는 로그인 후 이동 경로를 `/auth/profile`로 설정하지만 같은 테스트의 관리자 로그인 기대값은 `/auth/admin`이다. 현재 구현은 공통 설정값인 `/auth/profile`을 반환하므로 assertion이 실패한다.

이는 이번 검증만의 추가 테스트가 아니라 `.github/workflows/deploy-aws.yml`에 포함된 인증 테스트다. 따라서 기능 코드와 테스트 중 어느 쪽이 올바른 계약인지 확정하고 정합성을 맞추기 전에는 현재 저장소 기준 배포 검증이 통과한다고 볼 수 없다.

## 7. 최종 판정 및 후속 조치

| 구분 | 상태 |
|---|---|
| 서비스 배포 | 완료 — 운영 주소 접속 가능 |
| v05 모델 서비스 연동 | 완료 — `v05_05_dl` 운영 표시 확인 |
| 자동 배포 검증 | 부분 완료 — 인증 테스트 1건 실패 |
| 기능·보안 QA | 부분 완료 — 기존 17건 실패 및 미실행 항목 존재 |
| 최종 배포 승인 | **보류** |

후속 조치는 다음 순서로 진행한다.

1. 비인증 API, 권역 우회, HTTPS, snooze 지속성 등 P0 결함을 수정한다.
2. 로그인 후 이동 경로 계약을 확정하고 인증 테스트와 구현을 일치시킨다.
3. 최종 모델 산출물의 보관 위치, 버전, 체크섬과 재생성 절차를 확정한다.
4. 배포 산출물에 commit SHA 또는 build ID를 남긴다.
5. 동일 배포본에서 기존 실패 17건과 NOT RUN 항목을 회귀하고, 배포 게이트를 다시 판정한다.
