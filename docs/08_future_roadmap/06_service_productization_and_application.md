# [로드맵 06] 서비스 상용화 및 성과 학습 폐루프

**문서 위치**: `docs/08_future_roadmap/06_service_productization_and_application.md`  
**작성일시**: 2026-08-05

---

## 1. 개요 및 배경

현재 서비스는 지역별 리뷰 공급 변화를 감지하고, 핵심 리뷰어를 선별한 뒤, Reviewer 360에서 근거를 검토하고 운영안을 저장하는 흐름까지 구현되어 있다.

```text
리뷰 공급 변화 감지
→ 대상 선정
→ 활동 근거 검토·관리자 판단
→ 개인 운영안 또는 지역 캠페인 저장
→ 내부 재검토·접촉·감사 이력 관리
```

다음 단계의 핵심은 모델 점수만 높이는 것이 아니라 **실제 실행 결과를 측정하고 운영 정책과 모델 개선에 다시 반영하는 폐루프(Closed Loop)**를 완성하는 것이다.

```text
위험 신호 감지
→ 운영자 검토
→ CRM·캠페인 실행
→ 30·60·90일 결과 관찰
→ 운영안 효과 비교
→ 정책·모델 개선
```

모델 점수는 보정된 이탈 확률이 아니라 상대적인 운영 검토 순위이며, 운영안은 효과 검증 전까지 운영 가설로 취급한다.

---

## 2. 현재 기준선과 해결해야 할 문제

현재 운영 모델 `v05_05_dl`은 2018년 선정·피처 마감 → 2019년 사후 검증 Test 6,533명에서 다음 결과를 기록했다.

| 지표 | 결과 |
|---|---:|
| Macro F1 | 0.5731 |
| Macro PR-AUC | 0.5962 |
| 활동 약화 Recall | 67.86% |
| 리뷰 활동 중단 Recall | 37.56% |
| 상위 20% Precision | 89.29% |
| 상위 20% Recall | 29.55% |

상위 검토 대상의 정확도는 높지만, 실제 위험군 전체를 넓게 포착하는 데에는 한계가 있다. 또한 현재 운영 이력은 서버에 저장되지만 외부 발송 채널과 실행 이후의 성과 데이터가 연결되지 않아 어떤 운영안이 효과적이었는지 검증할 수 없다.

따라서 다음 문제를 우선 해결한다.

1. 연 단위 집계로 인한 늦은 위험 신호 감지
2. 활동 약화와 완전 중단의 서로 다른 탐지 성능
3. CRM 발송·수신·반응 데이터 부재
4. 운영안별 효과를 비교할 실험 구조 부재
5. 운영 중 데이터·점수 분포 변화 감시 체계 부재

## 3. 단계별 고도화 과제

### 과제 3.1: CRM 실행 채널 연동

* 이메일, 앱 푸시, 인앱 메시지 등 실제 서비스가 보유한 채널과 연동.
* 발송·도달·열람·클릭·거부·실패 이벤트를 운영안과 연결해 저장.
* 수신 동의, 채널별 접촉 제한, 중복 발송 방지, 제외 대상 정책 적용.
* 자동 발송보다 운영자 승인형 실행부터 도입하고 검증 후 자동화 범위를 결정.
* 혜택은 긍정적인 리뷰 작성의 대가가 아니라 플랫폼·커뮤니티 재참여를 지원하는 방식으로 설계.

### 과제 3.2: 30·60·90일 성과 측정

다음 지표를 운영안 실행 전후에 관찰한다.

* 다음 리뷰까지 걸린 기간
* 관찰 기간 내 음식 관련 리뷰 수
* 활동 월 수와 작성 간격 변화
* 리뷰 활동 재개 여부
* 지역별 전체 리뷰 공급 변화
* 메시지 수신 거부와 과도한 접촉 지표

실험군과 대조군 또는 단계적 도입 집단을 구성해 자연 회복과 개입 이후 변화를 구분한다. 단순 전후 비교만으로 운영안의 인과 효과를 확정하지 않는다.

### 과제 3.3: 월 단위 조기경보 파이프라인

* 최근 12~24개월 슬라이딩 윈도우를 월 단위로 갱신.
* 최근 1·3·6개월 리뷰 수, 활동 월, 작성 간격 변화 피처 추가 검증.
* 월별 검토 순위 신규 진입·상승·해제 이벤트 제공.
* 데이터 품질과 운영 비용을 확인한 뒤 주간 마이크로배치 또는 이벤트 기반 갱신 검토.
* 미래 시점 정보가 입력 피처에 포함되지 않도록 시점별 스냅샷과 학습 계약 유지.

완전한 실시간 처리보다 월 단위 배치를 우선 도입해 조기 개입 가치와 운영 비용을 먼저 검증한다.

### 과제 3.4: 활동 약화·중단 분리 운영

현재 `v05_05_dl`은 활동 약화 탐지에서 개선됐지만 리뷰 활동 중단 Recall은 기존 v04보다 낮다. 하나의 모델로 모든 목적을 해결하기보다 운영 질문에 따라 큐를 분리한다.

* **활동 약화 조기관리 큐**: `v05_05_dl` 중심으로 최근 변화 대상 검토.
* **리뷰 활동 중단 방어 큐**: v04 점수 병기 또는 중단 탐지 전용 비교 모델 검증.
* 운영 처리 용량에 따라 Top 10%·20%·30%의 Precision·Recall 비교.
* 중단 탐지 개선이 약화 탐지와 중증 오분류를 악화시키지 않는지 함께 평가.
* 새 모델은 기존과 동일한 expanding-time OOF 및 분리된 Final Test 기준을 통과한 경우에만 교체 검토.

`v05_05_dl`에는 이미 Risk head와 conditional Stopped head를 사용하는 계층형 구조가 구현되어 있다. 따라서 2단계 분류 자체는 향후 기능이 아니라 현재 기준선이며, 다음 실험은 중단 탐지의 성능 균형과 운영 정책 개선에 초점을 둔다.

### 과제 3.5: 리뷰 텍스트 피처 검증

정량적 활동 피처가 포착하지 못하는 작성 패턴 변화를 검증한다.

* 리뷰 길이와 정보량 변화
* 어휘·문장 구성 변화
* 음식 카테고리와 주제 다양성 변화
* 최근 리뷰와 과거 리뷰 표현 벡터 간 변화

텍스트 피처는 사용자의 심리 상태나 의학적 상태를 추론하는 데 사용하지 않는다. `열정 저하`나 `심리적 애착 감소`로 단정하지 않고 **관찰 가능한 리뷰 작성 패턴 변화**로만 표현한다. 성능 개선 수치는 사전에 만들지 않으며 시간 분할 OOF와 별도 Test 결과로 검증한다.

### 과제 3.6: 모델·데이터 운영 모니터링

* 월별 입력 데이터 누락과 스키마 변경 감시
* 피처 분포와 위험 순위 분포 변화 확인
* 권역·도시·활동 규모별 성능 편차 점검
* 운영 처리량, 미검토 적체, 재검토 기한 경과 모니터링
* 모델·정책·피처 버전과 판단 당시 문맥 보존
* 재학습·모델 교체·롤백 기준 문서화

## 4. 실제 적용 가능 플랫폼

### 4.1 Yelp

현재 데이터와 제품 구조를 가장 직접적으로 적용할 수 있는 대상이다. Elite와 핵심 리뷰어 유지, 지역별 리뷰 콘텐츠 공급 관리, 커뮤니티 이벤트 운영을 하나의 흐름으로 연결할 수 있다.

### 4.2 Google Maps Local Guides

리뷰·사진·장소 정보에 지속적으로 기여하는 사용자 활동 변화를 탐지하는 구조에 적용할 수 있다. 실제 적용에는 플랫폼 내부 활동 데이터, 사용자 동의, 커뮤니티 및 콘텐츠 정책 준수가 필요하며 외부 공개 프로필 수집만으로 CRM 대상을 만들지 않는다.

### 4.3 Tripadvisor

여행·숙박·음식점 리뷰 기여자의 활동 변화 관리에 적용할 수 있다. 여행 계절성과 장기 방문 주기를 반영해 일시적인 비활동과 지속적인 활동 중단을 구분해야 한다.

### 4.4 국내 장소 리뷰 플랫폼

네이버 지도·카카오맵과 같은 장소 리뷰 서비스의 핵심 기여자 유지, 지역별 콘텐츠 부족 탐지, 신규 핵심 작성자 발굴에 적용할 수 있다. 플랫폼별 리뷰·사진·방문 인증 구조가 다르므로 Yelp 기준 코호트와 라벨을 그대로 사용하지 않고 다시 정의해야 한다.

### 4.5 다른 UGC·구독 서비스

행동량, 활동 주기, 탐색 범위가 시간에 따라 기록되는 서비스라면 동일한 운영 프레임을 확장할 수 있다. 예를 들어 커머스 콘텐츠 작성자, 게임 커뮤니티 기여자, B2B SaaS 관리자 계정 등에 적용할 수 있지만 각 도메인의 이탈 정의와 실행 수단을 별도로 검증해야 한다.

## 5. 권장 우선순위

| 단계 | 우선 과제 | 완료 판단 기준 |
|---|---|---|
| 1 | CRM 실행 이벤트와 성과 데이터 계약 | 발송부터 30·60·90일 관찰까지 운영안 단위로 연결 가능 |
| 2 | 월 단위 조기경보 | 시점 누수 없이 월별 신규·상승·해제 대상 재현 가능 |
| 3 | 활동 약화·중단 분리 정책 | 동일 Test에서 목적별 Precision·Recall·중증 오분류 비교 완료 |
| 4 | 운영안 효과 실험 | 실험군·대조군 또는 단계적 도입 결과 축적 |
| 5 | 텍스트·추가 피처 실험 | 기존 기준선 대비 시간 OOF 개선과 별도 Test 검증 |
| 6 | 모델 재학습 폐루프 | 성능·운영·공정성 기준을 충족한 모델만 승인·롤백 가능 |

모델 교체보다 실행·측정 데이터 계약을 먼저 완성한다. 실제 개입 결과가 쌓여야 운영안 추천과 모델 고도화가 서비스 성과로 이어졌는지 검증할 수 있다.

---

## 6. 기대 효과

* 활동 변화 발생과 운영 검토 사이의 시차 단축
* 활동 약화와 리뷰 활동 중단에 맞는 서로 다른 운영 정책 제공
* 운영안별 효과와 부작용을 데이터로 비교
* 운영자의 처리 용량에 맞춘 검토 범위 조정
* 모델 성능, 실행 과정, 콘텐츠 공급 변화를 연결한 지속 개선 체계 구축

효과 수치와 CRM ROI는 실행 데이터가 축적되기 전까지 단정하지 않는다.
