## 1. 프로젝트 목적과 범위

### 1.1 해결하려는 문제

Yelp의 핵심 리뷰어는 음식점 정보의 양과 최신성을 유지하는 핵심 콘텐츠 생산자다. 리뷰 활동이 약화되거나 중단되면 지역별 리뷰 공급 감소, 신규 음식점 정보 부족, 검색·추천 품질 저하로 이어질 수 있다.

본 프로젝트는 모델 점수를 보여주는 분석 대시보드에 그치지 않고 운영자가 다음 업무를 수행할 수 있게 한다.

운영 서비스의 제품 축은 다음 세 가지다.

1. 지역별 리뷰 공급 변화 및 이상 탐지
2. 기존 핵심 리뷰어의 활동 약화·중단 예측과 우선 검토
3. 신규 핵심 리뷰어 유입 변화 관찰 및 우선 검토 대상 연결

```text
리뷰 공급 변화 감지
→ 감소·둔화 권역과 원인 확인
→ 우선 검토 리뷰어 선별
→ Reviewer 360에서 활동 근거 확인
→ 관리자 판단
→ 개인 특별 관리안 또는 지역 활성화 운영안 저장
→ 운영 이력과 30·60·90일 관찰 계획 확인
```

### 1.2 핵심 목표

1. 미래 정보를 사용하지 않는 롤링 코호트와 24개월 행동 시계열을 구축한다.
2. 향후 12개월의 `retained`·`weakened`·`stopped` 상태를 예측한다.
3. 위험 순위 상위 대상을 제한된 운영 자원으로 검토할 수 있게 한다.
4. 모델 판단과 활동 근거를 운영자의 최종 판단 및 운영안으로 연결한다.
5. 권역·도시별 리뷰 공급 변화와 핵심 리뷰어 변화를 함께 제공한다.
6. 모델·데이터·운영 한계와 QA 상태를 투명하게 공개한다.

### 1.3 현재 포함 범위

- Yelp User·Review·Business 데이터 결합과 음식 관련 업체 범위 적용
- 사용자×선정 연도 롤링 코호트와 24개월 시계열 생성
- ML 정적 피처와 DL 시계열·라이프사이클 피처 생성
- ML·DL 후보 비교와 `v05_05_dl` 최종 선정
- Expanding-Time OOF 검증 및 학습과 분리된 Final Test 평가
- 위험 순위 기반 Top 1,000 및 상위 20% 운영 정책 평가
- React 운영 화면, FastAPI, MySQL 기반 조회·판단·운영안 저장
- 권역·도시 리뷰 공급, 신규 핵심 리뷰어, 활동 반경, 음식점 후보 제공
- 관리자·운영자·조회 전용 역할과 관리자 설정 화면
- 관리자 UI QA 문서 및 실행 결과 관리

## 2. 핵심 용어와 데이터 기준

### 2.1 리텐션 상태

| 상태 | 정량 정의 | 운영 해석 |
|---|---|---|
| `retained` | 타깃 연도 음식 관련 리뷰 10건 이상이며 활동 월 3개월 이상 | 파워 지위 유지 |
| `weakened` | 타깃 연도 리뷰가 1건 이상이지만 유지 기준 미충족 | 활동 약화 |
| `stopped` | 타깃 연도 음식 관련 리뷰 0건 | 리뷰 활동 중단 |

`stopped`는 계정 탈퇴나 실제 생활 변화가 아니라 데이터에서 관찰되는 음식 관련 리뷰 활동 중단을 뜻한다.

### 2.2 시간 구조

```text
과거 24개월 행동 관찰
→ 선정·피처 마감 2018
→ 사후 상태 검증 2019
```

- 학습 범위: 선정 연도 2010~2017
- OOF 검증: Expanding-Time 5-Fold × 3 seeds, 공통 표본 24,596건
- Final Test: 학습과 분리된 2018년 선정 코호트 6,533명
- 운영 화면 비교: 2017년 비교 → 2018년 선정·피처 마감 → 2019년 사후 검증
- 2019년 사후 결과는 운영 당시 알 수 없는 정보이므로 기본 운영 화면에서 숨기거나 사후 검증으로 구분한다.

전체 코호트·권역 이력 37,953행은 개발 코호트 31,420행과 Final Test 6,533행으로 구성된다. OOF 24,596행은 개발 코호트 중 2013~2017년의 공통 평가 표본이며, 2010~2012년 6,824행은 초기 Expanding-Time Fold의 학습에만 사용된다.

### 2.3 점수와 운영 정책

- `risk_score`와 클래스 점수는 위험 순위를 정하기 위한 모델 점수이며 보정된 확률이 아니다.
- `이탈 가능성 84%`처럼 확률로 단정하지 않는다.
- 모델 판단과 관리자 판단을 시각적·개념적으로 구분한다.
- Primary CRM 정책은 위험 순위 상위 20%, 1,307명을 검토 대상으로 사용한다.
- Precision@1000은 모델 후보 비교와 제한된 운영 자원 평가 지표로 사용한다.
- 운영안과 캠페인은 효과가 검증된 처방이 아니라 운영자가 검토할 가설이다.

### 2.4 공간 정보

- 권역과 도시는 사용자의 거주지가 아니라 음식점 리뷰 활동을 집계한 운영 단위다.
- `생활 반경` 대신 `맛집 탐방 반경` 또는 `리뷰 활동 반경`을 사용한다.
- 음식점 위치는 공개된 업체 위치이며 사용자의 실제 이동 경로가 아니다.
- 도시 운영 순위에는 선정 연도 활동 리뷰어 30명 이상, 리뷰 100건 이상인 최소 표본 기준을 적용한다.

## 3. 시스템 구성

```text
React 운영 서비스 (`app/`)
    ↓
FastAPI (`api/`)
    ↓
MySQL (`yelp_data`)
    ↓
공통 운영 판단 로직 (`shared/retention/`)
```

- React의 현재 런타임 데이터 경로는 FastAPI와 MySQL이다.
- `app/src/data/*.json`은 정합성 확인과 복구용 export이며 API 실패 시 자동 폴백하지 않는다.
- 위험 유형·근거·전략 판단과 프로필 정규화의 기준 구현은 `shared/retention/`이다.
- 과거 Streamlit 앱은 `archive/app_streamlit_v04/`에 보존하며 현재 운영 화면이 아니다.

### 5.2 Final Test

Final Test는 모델 선정에 사용하지 않은 이후 시점의 일반화 검증이다. 평가 전에 별도의 Final Test 합격 임계값을 확정하지 않았으므로 OOF 수락 기준을 소급 적용해 PASS 또는 FAIL로 판정하지 않는다. 결과는 OOF 대비 성능 변화와 배포 위험을 검토하는 근거로 사용한다.

| 평가 항목 | 결과 |
|---|---:|
| Test 표본 | 6,533명 |
| Macro F1 | 0.5731 |
| Macro PR-AUC | 0.5962 |
| Balanced Accuracy | 0.5621 |
| Weakened Recall | 67.86% |
| Stopped Recall | 37.56% |
| 중증 오분류율 | 1.81% |
| Precision@1000 | 89.90% |
| Top 20% 대상 | 1,307명 |
| Top 20% Precision | 89.29% |
| Top 20% Recall | 29.55% |
| Top 20% Lift | 1.48배 |

가중치와 임계값은 Final Test 평가 전에 고정했다. OOF 결과와 Final Test 결과를 섞어서 단일 성능처럼 표현하지 않는다.

| 지표 | OOF | Final Test | 변화 | 판정 |
|---|---:|---:|---:|---|
| Macro F1 | 0.5763 | 0.5731 | -0.0032 | 검증 완료·수락 판정 미적용 |
| Macro PR-AUC | 0.5980 | 0.5962 | -0.0018 | 검증 완료·수락 판정 미적용 |
| Precision@1000 | 90.60% | 89.90% | -0.70%p | 검증 완료·수락 판정 미적용 |

Final Test용 수락 기준이 필요하면 다음 평가 전에 허용 성능 저하폭과 최소 운영 지표를 확정해야 한다. 현재 결과를 본 뒤 임계값을 새로 정해 소급 판정하지 않는다.
