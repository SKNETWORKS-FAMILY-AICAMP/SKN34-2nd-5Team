## 2. 작성 기준

- 역할은 최종 역할 분담 노션과 실제 산출물을 함께 검토하여 주 담당과 협업·검토로 기록한다.
- 진행 기간은 노션 회의 일정과 Git에서 확인되는 수행 범위를 사용하며, 확인되지 않은 세부 날짜는 임의로 만들지 않는다.
- 완료는 산출물과 근거가 확인된 경우에만 사용한다. 기능 구현과 최종 배포 승인은 구분한다.
- 상세 수락 기준과 범위 제외 항목은 [프로젝트 요구사항 명세서](./project_requirements.md), 결함 현황은 [관리자 UI QA 결과](../qa/ADMIN_UI_QA_EXECUTION_2026-08-05.md)를 따른다.
- 참고용 노션의 별도 고도화 제안은 현재 WBS 범위에서 제외한다.

### 상태

| 상태 | 의미 |
|---|---|
| 완료 | 계획한 산출물과 수행 근거가 확인됨 |
| 부분 완료 | 핵심 산출물은 있으나 일부 문서·검증·수락 기준이 남음 |
| 보류 | 선행 결함 또는 배포 게이트로 최종 승인을 진행할 수 없음 |
| 미검증 | 산출물의 위치 또는 검증 결과를 확인하지 못함 |
