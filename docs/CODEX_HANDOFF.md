# Codex Project Handoff

## 1. 프로젝트 한 줄 정의

활발하게 음식 관련 리뷰를 작성하던 파워 리뷰어의 활동 변화를 사용해
향후 리뷰 활동 이탈을 예측하고 운영 개입 대상을 선정한다.

## 2. 해결하려는 비즈니스 문제

파워 리뷰어가 떠나면 다음 문제가 발생할 수 있다.

- 리뷰 콘텐츠 감소
- 신규 음식점 정보 부족
- 검색 품질 저하
- 사용자의 방문 의사결정 약화
- 지역별 리뷰 공급 부족
- 광고 상품 가치 저하

현재 우선순위는 핵심 콘텐츠 생산자 유지와 CRM 대상 선정이다.

## 3. 모델링 문제

- 지도학습
- 이진 분류
- churn=1: 타깃 연도 음식 관련 리뷰 0건
- churn=0: 타깃 연도 음식 관련 리뷰 1건 이상
- 선정 연도 Y → 관찰 연도 Y+1 → 타깃 연도 Y+2

## 4. 파워 리뷰어 기준

- 선정 연도 음식 관련 리뷰 10건 이상
- 활동 월 3개월 이상
- 관찰 연도 하반기 리뷰 1건 이상

기준값은 `configs/analysis_config.yaml`에서 관리한다.

## 5. 음식 관련 데이터 범위

Restaurants와 선별된 미식 방문형 카테고리를 사용한다.

- Restaurants: 52,268개 업체
- 미식 방문형 추가 업체: 5,888개
- 최종 업체: 58,156개
- 최종 리뷰: 4,950,264개

`Food` 전체는 Shopping, Drugstores, Grocery 등이 포함되므로 사용하지 않는다.

## 6. 롤링 코호트

- 전체 표본: 21,601개 사용자-연도 표본
- 이탈 표본: 3,386개
- 학습: 선정 연도 2009~2015
- 검증: 선정 연도 2016
- 테스트: 선정 연도 2017
- 동일 사용자의 연도별 표본은 존재할 수 있음
- 시간 순서에 따른 분할을 유지해야 함

## 7. 핵심 피처

최종 Core 피처 43개:

- 활동량 15개
- 작성 간격 13개
- 음식점 탐색 15개

추가 검증 피처:

- 카테고리 다양성
- 탐방 반경
- 평점 변화

Useful·Cool·Funny 반응은 미래 정보 누수 가능성 때문에 현재 제외했다.

## 8. 최종 모델

- HistGradientBoosting
- Validation PR-AUC: 0.4032
- Test PR-AUC: 0.4264
- Test ROC-AUC: 0.8125

Primary 운영 정책:

- 위험 점수 상위 20% 관리
- 대상 832명
- 실제 이탈자 포착 346명
- Precision 41.59%
- Recall 51.64%
- Lift 2.58배

위험 점수는 보정된 확률이 아니라 순위화 점수다.

## 9. 서비스 방향

분석 결과를 전시하는 대시보드가 아니라 운영자가 다음 행동을 결정하는 서비스다.

- 오늘 관리할 리뷰어 확인
- 위험 리뷰어 검색 및 선별
- 개인별 위험 근거 확인
- 위험 유형에 맞는 개입 전략 결정
- 운영 결과 추적

## 11. 현재 UI 문제

- 모든 페이지가 같은 제목→필터→KPI→카드 구조
- 카드와 둥근 박스가 지나치게 많음
- 기본 Streamlit 컴포넌트 느낌이 강함
- 페이지별 작업 목적이 레이아웃에 반영되지 않음
- 정보 시각화보다 텍스트 카드에 의존함
- HTML 문자열이 화면에 노출되는 오류가 있음
- 기능적이지만 제품 디자인과 시각적 매력이 부족함

## 12. 현재 작업 목표

기존 기능과 데이터 연결을 보존하면서 UI 정보 구조를 전면 재설계한다.

먼저 다음 두 화면을 대표 화면으로 완성한다.

1. 운영 홈
2. 리뷰어 360

대표 화면의 방향을 확인한 후 나머지 페이지로 확장한다.
