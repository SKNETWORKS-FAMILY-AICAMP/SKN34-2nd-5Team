# Codex Project Handoff

## 1. 프로젝트 한 줄 정의

활발하게 음식 관련 리뷰를 작성하던 파워 리뷰어의 활동 변화를 사용해
향후 리뷰 활동 이탈을 예측하고 운영 개입 대상을 선정한다.

## 2. 해결하려는 비즈니스 문제

파워 리뷰어가 떠나면 다음 문제가 발생할 수 있다.

- 리뷰 콘텐츠 감소
- 신규 음식점 정보 부족
- 검색 품질 저하
- 사용자의 방문 의사결정 약화
- 지역별 리뷰 공급 부족
- 광고 상품 가치 저하

현재 우선순위는 핵심 콘텐츠 생산자 유지와 CRM 대상 선정이다.

## 3. 모델링 문제

- 지도학습 3클래스 분류 v03
- 파워 지위 유지: 타깃 연도 리뷰 10건 이상, 활동 월 3개월 이상
- 파워 지위 약화: 리뷰 1건 이상이며 리뷰 10건 미만 또는 활동 월 3개월 미만
- 리뷰 활동 중단: 리뷰 0건
- 기존 `churn`은 리뷰 활동 중단과 동일한 이진 보조 검증 라벨로 보존
- 선정 연도 Y → 관찰 연도 Y+1 → 타깃 연도 Y+2

## 4. 파워 리뷰어 기준

- 선정 연도 음식 관련 리뷰 10건 이상
- 활동 월 3개월 이상
- 관찰 연도 하반기 리뷰 1건 이상

기준값은 `configs/analysis_config.yaml`에서 관리한다.

## 5. 음식 관련 데이터 범위

Restaurants와 선별된 미식 방문형 카테고리를 사용한다.

- Restaurants: 52,268개 업체
- 미식 방문형 추가 업체: 5,888개
- 최종 업체: 58,156개
- 최종 리뷰: 4,950,264개

`Food` 전체는 Shopping, Drugstores, Grocery 등이 포함되므로 사용하지 않는다.

## 6. 롤링 코호트

- 전체 표본: 21,601개 사용자-연도 표본
- 이탈 표본: 3,386개
- 학습: 선정 연도 2009~2015
- 검증: 선정 연도 2016
- 테스트: 선정 연도 2017
- 동일 사용자의 연도별 표본은 존재할 수 있음
- 시간 순서에 따른 분할을 유지해야 함

## 7. 핵심 피처

최종 Core 피처 43개:

- 활동량 15개
- 작성 간격 13개
- 음식점 탐색 15개

추가 검증 피처:

- 카테고리 다양성
- 탐방 반경
- 평점 변화

Useful·Cool·Funny 반응은 미래 정보 누수 가능성 때문에 현재 제외했다.

## 8. 최종 모델

v03 프로토타입 기준 모델:

- 다중 LogisticRegression
- L1, C=0.1, class_weight=balanced
- Core 43개 피처
- 확장형 시간 5-Fold
- Test Macro F1: 0.5754
- Test Macro PR-AUC: 0.5986

Primary 운영 정책:

- `weakened_score + stopped_score` 통합 우선순위 상위 20%
- 대상 832명
- 실제 지위 상실 포착 773명
- 지위 상실 Precision 92.91%
- 지위 상실 Recall 29.53%
- Lift 1.48배
- 중단 포착 329명, Recall 49.10%
- 약화 포착 444명, Recall 22.79%

클래스별 모델 점수는 보정된 상태 확률이 아니며 통합 큐는 관리자의
우선 검토 순위로 사용한다. 기존 v02 이진 모델은 비교 기준으로 보존한다.

## 9. 서비스 방향

분석 결과를 전시하는 대시보드가 아니라 운영자가 다음 행동을 결정하는 서비스다.

- 오늘 관리할 리뷰어 확인
- 위험 리뷰어 검색 및 선별
- 개인별 위험 근거 확인
- 위험 유형에 맞는 개입 전략 결정
- 운영 결과 추적

## 10. Streamlit 화면

- 운영 홈
- 통합 리뷰어 관리
- 리뷰어 360 · 리뷰어 관리 내부 상세
- 리텐션 플레이북
- 지역 콘텐츠 위험 — 고도화 예정
- 모델 신뢰 센터
- 확장 로드맵

## 11. 현재 UI 문제

- 모든 페이지가 같은 제목→필터→KPI→카드 구조
- 카드와 둥근 박스가 지나치게 많음
- 기본 Streamlit 컴포넌트 느낌이 강함
- 페이지별 작업 목적이 레이아웃에 반영되지 않음
- 정보 시각화보다 텍스트 카드에 의존함
- HTML 문자열이 화면에 노출되는 오류가 있음
- 기능적이지만 제품 디자인과 시각적 매력이 부족함

## 12. 현재 작업 상태

- `final_test_retention_profiles_v03.parquet`을 기본 프로젝트 프로필로 연결
- 운영 홈을 통합 상위 20% 검토 큐 중심으로 전환
- 리뷰어 관리를 3클래스 점수·통합 순위·행동 신호 중심으로 전환
- 리뷰어 360에 실제 개인 변화와 관리자 세션 임시 판단 구조 적용
- 실제 정답은 검증 모드에서만 표시
- 영구 판단 저장·CRM 실행·성과 추적은 고도화 예정

다음 단계는 리텐션 플레이북과 모델 신뢰 센터를 v03 기준으로 전환하고,
지역 콘텐츠 위험과 로드맵의 내비게이션 위치를 정리하는 것이다.
