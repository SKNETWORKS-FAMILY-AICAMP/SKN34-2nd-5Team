# DEC-009. v03 통합 우선순위 축 재정의

| 항목 | 내용 |
|---|---|
| 상태 | 승인 |
| 적용 버전 | v03 |
| 결정 대상 | 통합 우선순위 등급(`risk_tier`) 구조 |
| 기존 결정 | DEC-006 파워 리뷰어 CRM 타기팅 정책, DEC-008 파워 리뷰어 리텐션 상태 정의 |
| 분석 범위 | Restaurants + 선별된 미식 방문형 업체 |

## 1. 배경 — 왜 재정의가 필요한가

DEC-006은 v02 이진 이탈(`churn`) 기준으로 상위 5%/20%/40% 4단계 등급(긴급 관리/집중 관리/관찰 대상/일반)을 정의했다. 당시 전체 이탈률은 16.1%로 낮아 등급 간 이탈률 격차가 컸다(긴급 53.85% vs 일반 5.57%, Lift 3.34배~0.35배).

v03는 이탈 정의가 `churn`(완전 중단)에서 `지위 상실`(약화+중단, DEC-008)로 확장되며 기저율이 62.98%로 크게 올랐다. 같은 5/20/40% 컷값을 v03 통합 우선순위(`priority_top_percent`)에 그대로 적용하면 다음과 같다.

| 등급 | 구간 | 인원 | 지위 상실률 | Lift |
|---|---:|---:|---:|---:|
| 긴급 관리 | 상위 5% | 207명 | 97.6% | 1.55× |
| 집중 관리 | 상위 5~20% | 624명 | 91.4% | 1.45× |
| 관찰 대상 | 상위 20~40% | 831명 | 85.8% | 1.36× |
| 일반 | 하위 60% | 2,495명 | 45.4% | 0.72× |

상위 40% 구간 내부(97.6% → 91.4% → 85.8%)는 서로 12%p 차이에 불과해 "긴급/집중/관찰"이라는 이름이 암시하는 위험도 차이를 데이터가 뒷받침하지 못한다. 반면 상위 40%와 하위 60% 사이(85.8% vs 45.4%)에는 40%p의 명확한 격차가 있다. 즉 이 라벨 정의에서 의미 있는 경계는 사실상 하나(상위 40% 안/밖)뿐이다.

## 2. 결정

4단계 위험 등급(`risk_tier`: 긴급 관리/집중 관리/관찰 대상/일반)을 v03 운영 기본 화면에서 폐기하고, 서로 독립된 두 축으로 대체한다.

### 축 1 — 검토 우선순위 (얼마나 급한가)

기존 통합 상위 20% 정책(DEC-006 §1, CODEX_HANDOFF §8)을 그대로 유지하되, 데이터가 뒷받침하지 못하는 3단계 세분화는 없애고 이진 구분만 사용한다.

| 구분 | 조건 | 인원 | 지위 상실 Precision | Lift |
|---|---|---:|---:|---:|
| 통합 검토 대상 | 통합 우선순위 상위 20% | 832명 | 92.91% | 1.48× |
| 일반 모니터링 | 나머지 80% | 3,325명 | — | — |

기존 `selected_for_crm`(`crm_target`) 컬럼을 그대로 사용한다. 새 컬럼을 만들지 않는다.

### 축 2 — 개입 방향 (무엇을 해야 하는가)

DEC-008 §5의 판단 기준을 등급 축으로 승격한다.

| 구분 | 조건 | 권장 방향 |
|---|---|---|
| 약화 우세 | `predicted_state = 1` | 활동 회복 플레이북 검토 |
| 중단 우세 | `predicted_state = 2` | 복귀·재활성화 플레이북 검토 |
| 유지 우세 | `predicted_state = 0` | 관찰 유지 |

기존 `predicted_state`/`model_judgment` 컬럼을 그대로 사용한다.

## 3. 등급 명칭 변경

| 기존 (v02 유래, 4단계) | 신규 |
|---|---|
| 긴급 관리 / 집중 관리 / 관찰 대상 | 통합 검토 대상 (축 1, 상위 20%) |
| 일반 | 일반 모니터링 (축 1, 나머지) |
| (없음) | 약화 우세 / 중단 우세 / 유지 우세 (축 2) |

## 4. 처리 용량(capacity) 세분화가 필요한 경우

통합 검토 대상(832명) 내부에서 "먼저 볼 순서"가 필요하면 위험도 차이가 아니라 **처리 순서**로만 안내한다.

- `priority_rank` 숫자 순위를 그대로 노출한다.
- "긴급/집중"처럼 위험도가 다르다는 인상을 주는 명칭을 사용하지 않는다.
- 필요 시 "상위 50명씩" 같은 처리 배치(batch) 단위로만 안내하고, 배치 자체가 위험 등급을 의미하지 않음을 화면에 명시한다.

## 5. 기존 코드 영향

- `app/core/data.py`의 `_normalize_profiles`는 이미 축 1에 해당하는 `crm_target_label`("통합 상위 20% 검토 대상"/"일반 모니터링")을 생성하고 있다. v03 화면은 4단계 `risk_tier` 대신 이 컬럼을 사용하도록 전환한다.
- `_derive_risk_tiers()`와 관련 차트(`tier_distribution`, `tier_churn_rate`, `score_histogram`의 `risk_tier` 색상 매핑)는 v02 비교 기준 화면에서만 사용하고 v03 기본 화면에서는 사용하지 않는다.
- `app/core/insights.py`의 `classify_risk_type()`이 참조하는 `risk_tier == "일반"` 폴백 조건은 축 1(`crm_target == 0`) 기준으로 교체한다.
- `app/views/playbook.py`의 후보 표 `등급` 컬럼은 축 1(통합 검토 대상 여부) + 축 2(모델 판단)로 교체한다.
- 위 항목은 Stage 3(리텐션 플레이북 v03 전환) 진행 시 별도 승인을 받아 반영한다. 본 문서는 정의만 확정하며 코드를 변경하지 않는다.

## 6. v02와의 관계

DEC-006의 4단계 등급과 5/20/40% 컷값은 v02 이진 모델 비교 기준으로 보존한다. v03 운영 기본 화면에는 적용하지 않는다.

## 7. 재검토 조건

다음 상황에서는 본 결정을 재검토한다.

- CRM 실제 처리 가능 인원이 확정되어 상위 20% 자체를 조정해야 하는 경우
- 지위 상실 정의(DEC-008)가 변경되어 기저율이 달라지는 경우
- 약화·중단 우세 판단 임계값(0.36/0.45)이 변경되는 경우
- 지역별 리뷰 공급 위험 등 새로운 우선순위 축이 추가되는 경우
