## 1. 프로젝트 개요

### 1.1 프로젝트명

**Yelp 파워 리뷰어의 미식 번아웃 예측**

> 파워 리뷰어의 과거 음식 관련 리뷰 활동 변화를 이용하여 향후 리뷰 활동 이탈을 예측하고, 플랫폼 운영팀이 우선 관리할 리뷰어와 적절한 개입 전략을 결정할 수 있도록 지원하는 지도학습 기반 이진 분류 프로젝트

본 프로젝트에서 `미식 번아웃`은 심리적·의학적 번아웃이 아니다. 활발하게 활동하던 리뷰어의 리뷰 작성량, 작성 주기, 음식점 탐색 범위 등이 감소하며 리뷰 활동 중단으로 이어질 수 있는 **행동 기반 이탈 위험 상태**를 의미한다.

### 1.2 프로젝트 소개

Yelp 데이터를 활용하여 활발하게 음식 관련 리뷰를 작성해 온 파워 리뷰어의 활동 변화를 분석하고, 미래 타깃 연도의 리뷰 활동 이탈 여부를 예측한다.

단순한 리뷰 수 감소만 확인하지 않고 다음 행동 변화를 함께 검토한다.

- 리뷰 작성량 및 활동 월 감소
- 리뷰 작성 간격과 최근성 변화
- 방문 음식점 수 감소
- 신규 음식점 탐색 변화
- 음식점 카테고리 다양성 변화
- 맛집 탐방 반경 변화
- 평균 평점 및 평가 성향 변화

최종 결과는 분석 결과를 나열하는 대시보드가 아니라, 플랫폼 운영자가 고위험 리뷰어를 발견하고 위험 근거를 확인한 뒤 개입 전략을 결정하는 **리뷰어 리텐션 운영 서비스**로 제공한다.

Yelp 데이터만으로 사용자의 실제 거주지, 직장, 생활권 이동을 확인할 수 없으므로 `생활 반경` 대신 `맛집 탐방 반경`, `리뷰 활동 반경`, `로컬 탐색 루틴`이라는 표현을 사용한다.

### 1.3 프로젝트 필요성

Yelp와 같은 지역 기반 리뷰 플랫폼에서 파워 리뷰어는 단순한 서비스 이용자가 아니라 플랫폼의 검색·추천·광고 가치를 뒷받침하는 핵심 콘텐츠 생산자다.

파워 리뷰어의 활동이 중단되면 다음 문제가 발생할 수 있다.

- 신규 리뷰 콘텐츠 감소
- 신규 음식점 및 지역 음식점 정보 부족
- 음식점 정보의 최신성 저하
- 검색 및 추천 품질 저하
- 다른 사용자의 방문 의사결정 약화
- 지역별 리뷰 콘텐츠 공급 불균형
- 플랫폼 광고 및 음식점 대상 서비스 가치 하락

활동을 완전히 중단한 뒤 재활성화하는 것보다 활동 감소 신호를 사전에 발견하고 원인에 맞게 개입하는 것이 효율적이다. 따라서 본 프로젝트는 모델 정확도만 높이는 것이 아니라, **운영팀이 제한된 CRM 자원으로 누구에게 먼저 개입할지 결정하는 것**을 핵심 비즈니스 문제로 정의한다.

### 1.4 프로젝트 목표

#### P0: 핵심 목표

1. 파워 리뷰어와 리뷰 활동 이탈의 정량 기준을 정의한다.
2. 시간 누수를 방지하는 롤링 코호트를 구축한다.
3. 리뷰 활동량·작성 간격·음식점 탐색 변화를 피처로 생성한다.
4. 미래 리뷰 활동 이탈을 예측하는 이진 분류 모델을 구축한다.
5. 위험 점수를 이용해 CRM 우선 관리 대상을 선정한다.
6. 운영자가 대상·위험 근거·권장 개입을 확인할 수 있는 서비스를 구현한다.

#### P1: 차별화 목표

1. 카테고리 다양성·탐방 반경·평점 변화의 추가 효과를 검증한다.
2. 리뷰어별 주요 위험 신호와 개입 전략을 연결한다.
3. 지역별 콘텐츠 공급 위험을 분석할 수 있는 구조를 설계한다.

#### P2: 향후 확장 목표

1. 실제 CRM 발송 및 개입 이력 관리
2. 개입 전후 성과 측정
3. 지역별 리뷰 콘텐츠 공급량 예측
4. 음식점 평판·광고 상품 위험 분석
5. 음식점 대상 B2B 분석 리포트

## 2. 문제 정의

### 2.1 핵심 분석 질문

> 파워 리뷰어의 리뷰 작성량, 작성 간격, 활동 월, 음식점 탐색 변화 등을 이용하여 향후 음식 관련 리뷰 활동 이탈을 예측하고, 운영팀이 관리할 고위험 리뷰어를 효과적으로 선별할 수 있는가?

### 2.2 세부 질문

1. 파워 리뷰어를 구분하는 적절한 활동 기준은 무엇인가?
2. 이탈자와 유지자의 관찰 기간 행동 변화에는 어떤 차이가 있는가?
3. 어떤 행동 변화가 이탈 위험 예측에 가장 크게 기여하는가?
4. 카테고리 다양성·탐방 반경·평점 피처가 핵심 피처보다 추가적인 예측력을 제공하는가?
5. 시간 순서가 다른 연도에도 모델 성능이 유지되는가?
6. 제한된 CRM 대상 비율에서 실제 이탈자를 얼마나 효과적으로 포착할 수 있는가?
7. 위험 신호에 따라 어떤 리텐션 전략을 제안할 수 있는가?
8. 향후 지역별 콘텐츠 공급 위험 분석으로 확장할 수 있는가?

## 3. 분석 및 모델링 정의

### 3.1 음식 관련 업체 범위

최종 분석 범위는 다음과 같다.

- `Restaurants` 업체
- 프로젝트 목적에 맞게 선별한 미식 방문형 업체

`Food` 전체는 Shopping, Drugstores, Grocery 등 미식 탐방과 직접 관련되지 않은 카테고리를 포함하므로 그대로 사용하지 않는다.

| 항목 | 결과 |
| --- | ---: |
| Restaurants 업체 | 52,268개 |
| 미식 방문형 추가 업체 | 5,888개 |
| 최종 음식 관련 업체 | 58,156개 |
| 최종 음식 관련 리뷰 | 4,950,264개 |

세부 선정 근거는 `docs/decisions/DEC-002_restaurant_scope.md` 및 최신 음식 범위 결정 문서를 따른다.

### 3.2 파워 리뷰어 기준

선정 연도 기준 다음 조건을 모두 만족한 사용자를 파워 리뷰어 후보로 정의한다.

- 음식 관련 리뷰 10건 이상
- 활동 월 3개월 이상
- 관찰 연도 하반기 음식 관련 리뷰 1건 이상

세부 기준값은 `configs/analysis_config.yaml`에서 관리하며, 결과 인원수를 코드에 하드코딩하지 않는다.

### 3.3 시간 구조

하나의 표본은 `사용자 × 선정 연도` 단위로 생성한다.

```text
선정 연도 Y
→ 관찰 연도 Y+1
→ 타깃 연도 Y+2
```

- 학습: 선정 연도 2009~2015
- 검증: 선정 연도 2016
- 테스트: 선정 연도 2017
- 최종 테스트 구조: 2017년 선정 → 2018년 관찰 → 2019년 이탈 검증

동일 사용자가 여러 선정 연도의 표본으로 포함될 수 있으나, 미래 연도의 정보를 과거 표본 학습에 사용하지 않도록 시간 순서로 분할한다.

### 3.4 이탈 기준

- `churn = 1`: 타깃 연도의 음식 관련 리뷰가 0건
- `churn = 0`: 타깃 연도의 음식 관련 리뷰가 1건 이상

이탈은 사용자의 Yelp 계정 탈퇴나 실제 생활 변화가 아니라 **데이터에서 관찰되는 음식 관련 리뷰 활동 중단**을 의미한다.

### 3.5 모델 출력 해석

- 모델링 문제: 지도학습 기반 이진 분류
- 최종 모델: HistGradientBoostingClassifier
- `risk_score`: 리뷰어의 상대적인 위험 순위를 산정하기 위한 모델 점수
- `risk_score`는 보정된 확률이 아니므로 `이탈 가능성 84%`처럼 표현하지 않는다.
- 운영 화면에서는 위험 점수, 위험 순위, 위험 등급 및 주요 신호로 표현한다.

### 3.6 운영 정책

Primary CRM 정책은 테스트 표본의 위험 점수 상위 20%를 관리 대상으로 선정하는 것이다.

| 지표 | 결과 |
| --- | ---: |
| 테스트 표본 | 4,157명 |
| 실제 이탈자 | 670명 |
| CRM 대상 | 832명 |
| 포착한 이탈자 | 346명 |
| Precision@Top20% | 41.59% |
| Recall@Top20% | 51.64% |
| Lift@Top20% | 2.58배 |

이 정책은 모든 사용자를 이탈/유지로 단정하기보다 제한된 운영 자원을 고위험군에 우선 배분하기 위한 기준이다.

## 4. 프로젝트 범위

### 4.1 현재 포함 범위

- Yelp Review·User·Business 데이터 검증
- 음식 관련 업체 범위 정의

- 머신러닝 분류 모델 비교 및 최종 모델 선정

- 의학적·심리적 번아웃 진단
- 실시간 이탈 예측
- 실제 Yelp 사용자 대상 메시지·혜택 발송

- 광고 매출 감소에 대한 직접적인 인과 검증

### 4.3 고도화 예정 범위

- 실제 개입 이력과 실행 상태 저장
- 개입 전후 리뷰 활동 변화 측정
- 사용자별 보정 이탈 확률 제공
- 지역별 파워 리뷰어 및 콘텐츠 공급 위험 분석
- 지역 앰배서더·리뷰 미션 운영
- 음식점 평판 위험 및 B2B 분석 리포트
- 사용자×음식점 단위의 단골 이탈 예측

## 8. 데이터 및 기술 제약

- 원본 Review 데이터가 약 699만 행이므로 전체 JSON을 화면이나 모델 실행 시 반복해서 불러오지 않는다.
- 중간 결과와 피처는 Parquet 등 효율적인 형식으로 저장한다.
- Check-in 데이터에는 `user_id`가 없어 사용자별 체크인 루틴 분석에 직접 사용할 수 없다.
- 리뷰 작성일은 실제 음식점 방문일과 다를 수 있다.
- 음식점 좌표는 리뷰 활동 위치일 뿐 사용자의 실제 생활권을 의미하지 않는다.
- 최근 기간 리뷰가 1건인 경우 작성 간격을 계산할 수 없으며, 이는 구조적 결측으로 처리한다.
- 공간 피처에는 장거리 여행과 지역 이동으로 인한 극단값이 포함될 수 있다.
- 누적 Useful·Cool·Funny 반응은 반응 발생 시점이 없어 시간 누수 위험이 있다.
- 데이터 수집 종료 시점이 가까운 연도는 가짜 이탈을 만들 수 있으므로 최종 타깃 연도를 2019년으로 제한한다.
- 동일 사용자의 연도별 표본이 존재하므로 무작위 분할 대신 시간 기반 분할을 유지한다.
- 위험 점수는 현재 보정된 이탈 확률이 아니다.
