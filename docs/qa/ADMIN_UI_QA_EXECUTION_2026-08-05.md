## 15. 권장 수정·재검증 순서

1. 운영 서비스를 HTTPS로 전환하고 HTTP 강제 리다이렉트·secure cookie를 적용한다.
2. retention API 전 구간에 인증 의존성을 적용하고 미인증 요청 401 회귀 테스트를 추가한다.
3. OPERATOR의 조회·쓰기 쿼리 모두 서버에서 담당 권역을 강제하고 URL/payload의 임의 region을 신뢰하지 않도록 수정한다.
4. 판단 저장 API와 프런트 직렬화의 스누즈 필드명·시간 형식·응답 역직렬화를 수정하고 `R360-06/08/09`를 묶어 재검증한다.
5. 큐 우측 Reviewer 360 링크에 현재 `source/region/city/status/sort`를 전달한다.
6. VIEWER와 권역 밖 OPERATOR의 쓰기 CTA를 UI에서 비활성화하되 서버 403도 유지한다.
7. 홈 순위 탐색의 다음 대상 계산과 마지막 순위 비활성 조건을 수정한다.
8. 판단 변경 감사 이력에 이전/새 값이 실제로 저장·노출되는지 확인한다.
9. `/trust`의 모바일 고정 너비를 제거하고 390px 회귀 테스트를 추가한다.
10. TRUST-05 및 대상 명단 CSV·삭제가 확정 요구사항인지 결정한 뒤 구현하거나 QA 기대 결과를 조정한다.
11. 접힌 설정 링크에 접근 가능한 이름과 툴팁을 추가한다.
12. `UPD-01~04`를 목표 AFTER 화면과 일치하게 반영한 뒤 같은 데이터로 다시 검증한다.
13. 실제 브라우저·장애 주입 환경에서 `AUTH-09`, `R360-03/05/12`, 알림 처리, API/DB·5xx 오류 케이스를 재실행한다.
