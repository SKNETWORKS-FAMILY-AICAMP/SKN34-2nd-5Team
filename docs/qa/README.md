# 관리자 UI QA 문서 안내

이 디렉터리는 Reviewer Retention 운영 서비스의 관리자 화면 QA 기준과 실행 결과를 관리한다.
테스트 정의와 실행 증적을 분리하여, 케이스 원본은 반복 사용하고 실행 결과는 날짜별로 보존한다.

## 문서 구성

| 문서 | 역할 | 갱신 시점 |
|---|---|---|
| [QA 계획](ADMIN_UI_QA_PLAN.md) | 목적, 범위, 시작·종료 조건, 테스트 데이터와 결함 등급 | 범위·정책·환경이 바뀔 때 |
| [QA 테스트 케이스](ADMIN_UI_QA_CASES.md) | A~K 전체 135개 케이스의 절차와 기대 결과 | 기능·요구사항이 바뀔 때 |
| [QA 흐름도](ADMIN_UI_QA_FLOWS.md) | 인증, 개인 판단, 권역 캠페인, 계정, 저장 검증의 E2E 순서 | 업무 흐름이 바뀔 때 |
| [2026-08-05 실행 결과](ADMIN_UI_QA_EXECUTION_2026-08-05.md) | A~K 실제 실행 상태, 증거, 결함, 테스트 데이터 복구 상태 | 해당 실행일의 QA를 진행할 때 |

## 권장 사용 순서

1. QA 계획에서 범위·계정·환경·복구 규칙을 확인한다.
2. 흐름도에 따라 관리자 E2E 경로를 선택한다.
3. 테스트 케이스에서 해당 ID의 절차와 기대 결과를 확인한다.
4. 날짜별 실행 결과에 `PASS`, `FAIL`, `PARTIAL`, `NOT RUN`과 실제 증거를 기록한다.
5. 쓰기 테스트 종료 후 판단·계정·명단·운영안 복구 상태를 기록한다.

## 최신 실행 요약

2026-08-05 기준 A~J 128건과 최종 배포 변경 회귀 K 7건을 합친 결과다. 제품 측 최종 배포 안내 후 회귀 테스트를 수행했지만 커밋 또는 빌드 식별자는 제공되지 않았다.

| 범위 | PASS | FAIL | PARTIAL | NOT RUN | 합계 |
|---|---:|---:|---:|---:|---:|
| A~J 기존 실행 | 92 | 13 | 6 | 17 | 128 |
| K 최종 배포 변경 회귀 | 3 | 4 | 0 | 0 | 7 |
| **통합** | **95** | **17** | **6** | **17** | **135** |

우선 확인할 결함은 다음과 같다.

1. 운영 서비스 HTTP 제공 및 인증 정보의 TLS 미적용
2. 미인증 retention 조회 API 노출
3. OPERATOR 담당 권역 조회·쓰기 제한 우회
4. Reviewer 360 스누즈 저장값 미복원
5. 큐에서 Reviewer 360 이동 시 필터·권역·도시 맥락 유실

상세 재현 절차와 나머지 결함은 [최신 실행 결과](ADMIN_UI_QA_EXECUTION_2026-08-05.md)의 `우선 조치가 필요한 결함`에서 확인한다.

최종 배포 변경 회귀에서는 다음 4건이 미통과했다.

1. 추천 권역 변경 이유 카드와 추천 후보 연결 버튼 미표시
2. 순유출 규모가 공급 감소 핵심 인사이트 문장에 통합되지 않음
3. 위험 매장 배지와 전년 대비 감소율 미표시
4. 지역 캠페인 Step3의 로컬 맛집 분류 미반영

## 기록 원칙

- 테스트 케이스 문서의 결과 열은 재사용 가능한 원본으로 유지하고, 실제 결과는 날짜별 실행 보고서에 기록한다.
- 실행 보고서를 구간별로 나누지 않는다. 같은 실행일의 A~K 결과와 추가 회귀는 한 문서에서 관리한다.
- 배포 환경·완료 시각·커밋 또는 빌드 식별자를 기록하고, 실행 중 배포가 바뀌면 영향 케이스를 새 배포에서 다시 실행한다.
- 모델 점수는 확률로 표현하지 않고 운영 우선순위 지표로 기록한다.
- 실제 데이터가 있으면 실제 값을 사용하며, 데모·합성 데이터는 명확히 표시한다.
- 비밀번호, 세션 쿠키, CSRF 값 등 비밀정보는 문서와 캡처에 남기지 않는다.
- QA 쓰기 데이터는 식별 가능한 접두어를 사용하고, 삭제할 수 없는 감사·접촉 이력은 보존 이유를 기록한다.

## 새 실행 보고서 작성 규칙

- 파일명: `ADMIN_UI_QA_EXECUTION_YYYY-MM-DD.md`
- 기준 문서와 실행 환경을 상단에 기록한다.
- A~K 135개 ID의 누락·중복 여부와 상태 합계를 확인한다.
- 결함에는 우선순위, 관련 케이스, 재현 절차, 실제·기대 결과, 영향, 복구 상태를 연결한다.
- 실행이 끝나면 이 README의 최신 실행 링크와 요약 수치를 갱신한다.
