## 1. 배경

현재 운영 서비스에는 위험 유형, 모델 판단, 관리자 판단이 공존한다. 각 분류의 역할이 화면마다 명확히 분리되지 않아 리뷰어 관리와 리텐션 플레이북의 목적이 겹쳐 보인다.

| 분류 | 예시 |
|---|---|
| 위험 유형 | 활동량 붕괴형, 작성 주기 이완형, 탐색 활동 축소형 |
| 모델 판단 | 유지 우세, 약화 우세, 중단 우세 |
| 관리자 판단 | 복귀 관리, 활동 회복 관리, 관찰 유지, 대상 제외 |

위험 유형은 활동 약화의 원인을 설명하는 분류이며, 플레이북은 이번에 무엇을 할지 제시해야 한다.

## 2. 결정

### 2.1 위험 유형

위험 유형은 리뷰어 관리에서 운영 대상을 찾고 원인을 파악하는 조회 조건으로 사용한다.

```text
위험 유형
= 활동 변화의 주된 원인 또는 관찰 신호
= 리뷰어 관리의 조회·정렬·세부 전략 분기 기준
```

현재 운영 화면에서 사용할 위험 유형은 아래 다섯 개로 통일한다.

| 위험 유형 | 의미 |
|---|---|
| 복합 위험형 | 활동량·작성 주기·탐색 활동 중 둘 이상에서 강한 약화 신호 |
| 활동량 붕괴형 | 리뷰 수 또는 활동 월 감소가 가장 강한 신호 |
| 작성 주기 이완형 | 마지막 리뷰 공백 또는 작성 간격 증가가 가장 강한 신호 |
| 탐색 활동 축소형 | 고유 음식점 수 또는 신규 탐색 감소가 가장 강한 신호 |
| 일반 모니터링형 | 강한 약화 신호가 확인되지 않은 상태 |

위험 유형의 수치 임계값은 현재 규칙 기반 프로토타입 값이다. 모델·데이터 담당자는 분포와 운영 효과를 검증한 뒤 별도 결정으로 확정한다.

### 2.2 모델 판단

모델 판단은 유지·약화·중단 점수 중 상대적으로 우세한 상태다.

```text
모델 판단
= 자동 운영 조치가 아님
= 우선순위와 검토 근거
```

| 모델 판단 | 의미 | 운영상 기본 해석 |
|---|---|---|
| 유지 우세 | 유지 점수가 상대적으로 우세 | 변화 지켜보기 후보 |
| 약화 우세 | 약화 점수가 상대적으로 우세 | 리뷰 활동 늘리기 후보 |
| 중단 우세 | 중단 점수가 상대적으로 우세 | 리뷰 다시 시작 유도 후보 |

클래스 점수와 통합 우선순위 점수는 보정 확률이 아니며, 자동 확정 상태로 표현하지 않는다.

### 2.3 관리자 판단

관리자 판단은 Reviewer 360에서 운영자가 활동 근거와 모델 판단을 검토한 뒤 이번 검토에서 취할 조치를 선택하는 값이다.

```text
관리자 판단
= 운영자의 조치 결정
= 모델 판단을 참고하되 자동으로 결정하지 않음
```

v04 화면 적용 제안값은 아래와 같다.

| 관리자 판단 | 의미 |
|---|---|
| 리뷰 다시 시작 유도 | 최근 활동이 사실상 멈췄거나 중단 신호가 강한 대상에게 재참여를 유도 |
| 리뷰 활동 늘리기 | 활동은 남아 있으나 리뷰 수·주기·탐색 활동이 약화된 대상의 활동 증가를 지원 |
| 변화 지켜보기 | 즉시 개입하지 않고 다음 활동 변화를 추가 확인 |
| 이번엔 제외 | 현재 검토·개입 큐에서는 제외하되 데이터와 이력은 보존 |

위 명칭은 화면 적용 전 팀의 최종 문구 확인이 필요하다.

### 2.4 관리자 판단 저장 범위

현재 관리자 판단은 단일 운영자 데모 기능으로 제공한다.

```text
현재 구현
- reviewer_id별 판단값 1개 저장
- 로컬 서버 파일에 저장
- 새로고침·서버 재시작 후 유지 가능
- 여러 세션은 같은 저장소를 공유

현재 미지원
- 운영자 인증
- 담당자 배정
- 판단 일시·사유·메모
- 다중 사용자 동시 편집
- 감사 이력
- CRM 발송·캠페인 실행
```

리뷰어 관리에는 관리자 판단별 필터를 추가하지 않는다. 현재 범위에서는 `전체 / 미검토 / 검토 완료`만 제공한다.

### 2.5 플레이북

리텐션 플레이북은 위험 신호 목록이 아니라 관리자 판단을 실제 다음 행동으로 연결하는 전략 가이드다.

```text
리텐션 플레이북
= 운영 판단에 맞는 다음 행동을 정하는 화면
```

플레이북의 주 조회 조건은 관리자 판단으로 한다.

```text
리뷰 다시 시작 유도
리뷰 활동 늘리기
변화 지켜보기
이번엔 제외
```

위험 유형은 플레이북 내부의 세부 전략 분기 조건으로, 모델 판단은 전략의 적합성과 우선순위를 설명하는 보조 근거로 사용한다.

## 3. 화면별 정보 구조

### 3.1 리뷰어 관리

리뷰어 관리는 “누구를 먼저 볼 것인가”를 결정하는 작업 목록이다.

```text
검토 상태
위험 유형
모델 판단
통합 검토 범위
통합 우선순위
```

관리자 판단은 리뷰어 관리의 별도 필터로 제공하지 않는다.

### 3.2 Reviewer 360

```text
활동 변화 확인
→ 위험 유형·핵심 신호 확인
→ 모델 판단 확인
→ 관리자 판단 선택
→ 연결된 플레이북 전략 확인
```

Reviewer 360에서 플레이북으로 이동할 때 전달하는 정보는 관리자 판단, 위험 유형, 모델 판단, 통합 우선순위, 리뷰어 ID다.

### 3.3 리텐션 플레이북

플레이북은 다음 두 방식으로 진입한다.

```text
1. Reviewer 360에서 특정 리뷰어의 판단 결과와 함께 진입
2. 전체 전략을 탐색하는 전략 라이브러리로 직접 진입
```

Reviewer 360에서 진입한 경우 관리자 판단을 기본 선택값으로 사용한다. 직접 진입한 경우에는 관리자 판단을 먼저 선택하고 위험 유형을 추가로 선택한다.

## 4. 관리자 판단별 플레이북 초안

아래 전략은 규칙 기반 운영 아이디어 초안이다. 개입 효과가 검증된 처방이나 자동 실행 규칙이 아니다.

### 4.1 리뷰 다시 시작 유도

| 항목 | 내용 |
|---|---|
| 적용 검토 조건 | 중단 우세 판단, 최근 리뷰 공백 장기화, 최근 활동 월·리뷰 수 급감 |
| 주요 확인 신호 | 마지막 리뷰 공백, 최근 리뷰 수, 활동 월, 탐색 활동 변화 |
| 1차 운영 행동 | 대상 적합성 확인 후 재참여 메시지 또는 개인 활동 리포트 제안 검토 |
| 세부 전략 | 작성 주기 이완형은 작성 재개 계기 중심, 복합 위험형은 운영자 검토 후 맞춤 제안 |
| 권장 채널 | 앱 내 메시지 우선 검토 |
| 고도화 필요 | 이메일·푸시·혜택 제공에는 수신 동의·언어·채널 정보 필요 |
| 성공 기준 초안 | 일정 기간 내 리뷰 재개 여부, 활동 월 재발생 여부 |

### 4.2 리뷰 활동 늘리기

| 항목 | 내용 |
|---|---|
| 적용 검토 조건 | 약화 우세 판단, 최근 활동은 있으나 리뷰 수·활동 월·탐색 활동이 감소 |
| 주요 확인 신호 | 리뷰 수 감소, 활동 월 감소, 작성 간격 증가, 고유 음식점 수 감소 |
| 1차 운영 행동 | 현재 관심사를 반영한 탐색·콘텐츠·리뷰 작성 계기 제안 검토 |
| 세부 전략 | 활동량 붕괴형은 리뷰 활동량 회복, 작성 주기 이완형은 루틴 회복, 탐색 활동 축소형은 신규 탐방 유도 |
| 권장 채널 | 운영자 검토 후 앱 내 메시지 또는 콘텐츠 노출 |
| 고도화 필요 | 개인화 추천에는 선호 카테고리·지역·채널 데이터 필요 |
| 성공 기준 초안 | 다음 기간 리뷰 수·활동 월·고유 음식점 수 회복 여부 |

### 4.3 변화 지켜보기

| 항목 | 내용 |
|---|---|
| 적용 검토 조건 | 유지 우세, 일반 모니터링, 일시적 감소 가능성, 활동 근거 부족 |
| 주요 확인 신호 | 최근 활동 재개 여부, 추가 약화 신호 발생 여부, 우선순위 변화 |
| 1차 운영 행동 | 캠페인 실행 없이 재검토 기준과 시점을 설정 |
| 세부 전략 | 일반 추천 또는 비개입 모니터링 |
| 권장 채널 | 즉시 실행 채널 없음 |
| 고도화 필요 | 재검토 알림·담당자 배정 |
| 성공 기준 초안 | 재검토 시점에 유지·회복·추가 약화 여부 |

### 4.4 이번엔 제외

| 항목 | 내용 |
|---|---|
| 적용 검토 조건 | 데이터 품질 문제, 최근 활동 회복 확인, 중복·오분류 가능성, 현재 운영 대상 외 |
| 주요 확인 신호 | 데이터 이상 여부, 최근 활동 변화, 제외 사유 |
| 1차 운영 행동 | 캠페인·메시지 미실행 |
| 세부 전략 | 제외 사유 기록, 향후 재편입 조건 설정 |
| 권장 채널 | 없음 |
| 고도화 필요 | 제외 사유·담당자·재검토 시점의 영구 이력 저장 |
| 성공 기준 초안 | 제외 대상의 재편입 필요 여부 및 오분류 여부 |

## 5. 위험 유형과 플레이북 세부 전략 연결

| 위험 유형 | 리뷰어 관리에서의 역할 | 플레이북 세부 전략 |
|---|---|---|
| 복합 위험형 | 복수 활동 신호가 약화된 대상 조회 | 우선순위 높은 복합 개입 검토 |
| 활동량 붕괴형 | 리뷰 수·활동 월 감소 대상 조회 | 리뷰 활동 늘리기 중심 |
| 작성 주기 이완형 | 리뷰 공백·작성 간격 증가 대상 조회 | 리뷰 다시 시작 또는 작성 루틴 회복 중심 |
| 탐색 활동 축소형 | 고유 음식점·신규 탐색 감소 대상 조회 | 신규 탐방·콘텐츠 탐색 유도 중심 |
| 일반 모니터링형 | 강한 약화 신호가 없는 대상 조회 | 변화 지켜보기 중심 |

## 6. 구현·데이터 영향

### 리뷰어 관리

기존 위험 유형·모델 판단·통합 검토 범위 필터는 유지한다. 관리자 판단별 리스트 필터, CRM 실행 필터, 담당자별 필터는 추가하지 않는다.

### Reviewer 360

관리자 판단 명칭, 모델 추천 문구, 플레이북 이동 시 전달 정보, 데모용 저장 범위 안내를 변경한다.

### 리텐션 플레이북

```text
첫 번째 조회 기준: 위험 유형 → 관리자 판단
위험 유형: 세부 전략 분기 조건
모델 판단: 보조 근거
```

### 향후 MySQL 고도화

향후 `operator_decisions` 테이블에는 아래 정보가 필요하다.

```text
decision_id
reviewer_id
model_version
manager_decision
risk_type
model_judgment
decision_reason
decision_owner
decided_at
playbook_id
review_due_at
```

이 테이블 생성과 실제 운영 이력 저장은 본 Decision의 현재 구현 범위에 포함하지 않는다.

## 7. 재검토 조건

- 위험 유형 임계값 검증 결과가 현재 규칙과 다른 경우
- v04 모델의 약화·중단 판단 기준이 변경되는 경우
- 실제 CRM 채널·수신 동의·담당자 정보가 연동되는 경우
- 플레이북별 개입 효과가 측정되어 전략 우선순위를 바꿔야 하는 경우
- 다중 운영자 판단·감사 이력이 제품 필수 기능이 되는 경우
