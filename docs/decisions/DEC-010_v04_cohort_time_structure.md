# DEC-010. v04 파워 리뷰어 코호트 및 예측 시간 구조 재정의

## 문서 정보

| 항목 | 내용 |
|---|---|
| 상태 | 제안 · 팀 검토 필요 |
| 적용 예정 버전 | v04 |
| 결정 대상 | 파워 리뷰어 후보, 예측 코호트, 시간 구조 |
| 관련 결정 | DEC-001, DEC-003, DEC-004, DEC-007, DEC-008, DEC-009 |

## 1. 배경

현재 v03은 `2017년 선정 → 2018년 관찰 → 2019년 검증` 구조를 사용한다. 최종 Test 코호트에는 2018년 하반기 음식 관련 리뷰 1건 이상이라는 연속성 조건도 포함되어 있다.

이 구조에서는 2018년 말에 2019년 상태를 예측하면서 대상자는 2017년 파워 리뷰어다. 따라서 팀에 공유한 파워 리뷰어 기준과 최종 Test 코호트 기준이 다르게 해석될 수 있고, 현재 파워 리뷰어의 다음 해 리텐션을 관리한다는 운영 질문과 대상 시점이 맞지 않는다.

## 2. 운영 질문

> 2018년 말 기준 파워 리뷰어 중, 2019년에 파워 지위를 유지·약화·중단할 가능성이 높은 사람은 누구인가?

## 3. 결정

### 3.1 파워 리뷰어 후보

파워 리뷰어 후보는 선정연도 `Y`에 아래 조건을 모두 충족한 사용자로 정의한다.

```text
선정연도 음식 관련 리뷰 10건 이상
AND
선정연도 활동 월 3개월 이상
```

v04 최종 Test의 선정연도는 2018년이다. 음식 관련 업체 범위는 DEC-007을 그대로 따른다.

### 3.2 연속성 조건 제거

기존의 `관찰연도 하반기 음식 관련 리뷰 1건 이상` 조건은 v04 파워 리뷰어 후보 및 예측 코호트 필터에서 제거한다.

2018년 전체 기준으로 이미 리뷰 10건 이상·활동 월 3개월 이상을 충족한 파워 리뷰어를 선정하므로, 추가 하반기 연속성 조건은 적용하지 않는다.

### 3.3 v04 시간 구조

```text
비교 기준 연도 Y-1
→ 이전 활동 패턴 및 변화 비교 기준

선정·예측 기준 연도 Y
→ 파워 리뷰어 선정
→ 모델 입력 피처 생성 시점

타깃 연도 Y+1
→ 유지·약화·중단 실제 상태 검증
```

최종 Test는 아래와 같다.

```text
2017년: 비교 기준 연도
2018년: 파워 리뷰어 선정 및 모델 입력 기준 시점
2019년: 실제 유지·약화·중단 상태 검증
```

모든 모델 입력은 2018년 12월 31일 이전 정보만 사용한다. 2019년 리뷰 수·활동 월·상태 라벨은 정답 생성과 검증에만 사용한다.

### 3.4 피처 사용 원칙

기존 v03 Core 43개 피처의 종류는 유지한다.

```text
활동량 15개
작성 간격 13개
음식점 탐색 15개
```

v04에서는 `2017년 baseline → 2018년 recent` 구조로 기존 피처값을 다시 계산·검증한다. 이는 새 피처 유형을 추가하는 작업이 아니라 새 v04 코호트에 맞춰 기존 피처를 재생성하는 작업이다.

### 3.5 이전 파워 리뷰어의 처리

2017년에는 파워 리뷰어였으나 2018년에는 리뷰 10건 또는 활동 월 3개월 기준을 충족하지 못한 사용자는 v04 예측 모델 대상에 포함하지 않는다.

이전 파워 리뷰어의 활동 회복·재참여 관리 큐는 고도화 예정으로 둔다.

### 3.6 타깃 라벨

2019년 유지·약화·중단 정의는 DEC-008을 그대로 따른다.

| 코드 | 상태 | 2019년 조건 |
|---:|---|---|
| 0 | 파워 지위 유지 | 리뷰 10건 이상 AND 활동 월 3개월 이상 |
| 1 | 파워 지위 약화 | 리뷰 1건 이상이며 리뷰 10건 미만 OR 활동 월 3개월 미만 |
| 2 | 리뷰 활동 중단 | 리뷰 0건 |

## 4. 학습·검증·Test 분할

원칙은 선정연도 기준 시간 순서 분할이다.

```text
학습: 선정연도 2010~2016 후보
검증: 선정연도 2017 후보
최종 Test: 선정연도 2018 → 타깃연도 2019
```

2010년 선정 코호트에서 2009년 비교 기준 데이터를 안정적으로 생성할 수 있는지는 사전 검증한다. 데이터 범위에 따라 최초 학습 연도는 조정할 수 있으며, 실제 사용 연도와 조정 사유는 모델 메타데이터에 기록한다.

## 5. v04 검증 및 승격 원칙

```text
v03 보존
→ v04 후보 코호트 생성
→ v04 피처 재생성
→ v04 학습·시간 5-Fold 검증
→ v03 대비 비교
→ 팀 승인
→ 승인 시 운영 기본 모델 전환
```

승인 전에는 v03 모델 파일, v03 Test 프로필 파일, Streamlit 기본 데이터 연결, v03 성능 수치를 변경하지 않는다.

### 필수 비교 지표

| 구분 | v03 | v04 |
|---|---:|---:|
| Test 코호트 수 | 4,157명 | 재계산 |
| 유지·약화·중단 분포 | 기존 결과 | 재계산 |
| Macro F1 | 0.5754 | 재계산 |
| Macro PR-AUC | 0.5986 | 재계산 |
| Macro ROC-AUC | 0.7798 | 재계산 |
| 약화 Recall | 54.67% | 재계산 |
| 중단 Recall | 58.51% | 재계산 |
| Top 10%·20%·30% Precision/Recall/Lift | 기존 결과 | 재계산 |

상위 20% 정책은 v03 비교 기준으로 보존한다. v04에서는 Top 10%·20%·30%를 비교한 뒤 실제 운영 처리 용량에 맞춰 재결정한다.

## 6. 필수 데이터 검증

- 2018년 파워 리뷰어 후보 수
- 사용자 ID 중복 여부
- 2017년 비교 기준 데이터가 없는 2018년 후보 수
- 전년 대비 감소율의 0 나누기·결측·무한값 발생 여부
- 2019년 타깃 리뷰·활동 월 데이터의 누락 여부
- Core 43개 피처 결측률 변화
- 음식 관련 업체 범위의 DEC-007 일치 여부
- 학습·검증·Test 간 시간 누수 여부

## 7. 영향 범위

v04 승인 후 롤링 코호트 생성, 피처 생성 기준 연도, 모델·프로필 Export, 메타데이터·리포트, Streamlit 데이터 계약과 화면 수치를 전환한다.

정합화 대상 문서는 DEC-001, DEC-003, DEC-004, DEC-008, DEC-009, PROJECT_REQUIREMENTS.md, BUSINESS_SCENARIOS.md, CODEX_HANDOFF.md, STREAMLIT_DATA_CONTRACT.md다.

## 8. 재검토 조건

- 실제 운영 주기가 월간·분기 단위로 확정되는 경우
- 2017년 비교 데이터가 부족해 피처 품질이 떨어지는 경우
- v04 성능 또는 운영 정책 효과가 v03보다 현저히 낮은 경우
- 이전 파워 리뷰어 회복 관리 기능을 제품 범위에 포함하는 경우
- 실제 CRM 처리 가능 인원이 확정되어 Top-K 정책을 바꿔야 하는 경우
