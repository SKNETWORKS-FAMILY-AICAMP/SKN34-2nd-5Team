# Streamlit Redesign Brief

## 현재 문제

- 모든 페이지가 비슷한 대시보드 구조를 사용함
- 큰 제목, 필터, KPI 카드, 표가 반복됨
- 카드가 많아 정보의 중요도 구분이 어려움
- 기본 Streamlit 컴포넌트 느낌이 강함
- 페이지별 사용 목적이 레이아웃에 반영되지 않음
- 텍스트와 숫자 위주이며 시각적 설명이 부족함
- 일부 HTML 문자열이 화면에 노출됨

## 목표

분석 결과를 전시하는 대시보드가 아니라
운영자가 위험 리뷰어를 발견하고 판단하고 개입하는
제품형 리뷰어 리텐션 운영 화면을 만든다.

## 대표 화면 우선순위

1. 운영 홈
2. 리뷰어 360
3. 위험 리뷰어 관리
4. 리텐션 플레이북

대표 화면의 디자인 방향을 확정한 후 나머지 페이지로 확장한다.

## 페이지별 역할

### 운영 홈

- 오늘의 운영 상황 파악
- 우선 관리 대상 확인
- 핵심 위험 신호 확인
- 관리 업무로 이동

### 위험 리뷰어 관리

- 위험 리뷰어 검색 및 필터링
- ~~대상 비교~~ (삭제 · 2026-07-26 — 워크리스트가 이미 통합 우선순위로 정렬되어 있고, 비교 후 이어지는 실행 동작이 없어 실효성이 낮다고 판단)
- CRM 관리 대상 선정
- 개인 상세 화면 이동

### 리뷰어 360

- 개인의 활동 변화 확인
- 위험 원인 확인
- 전체 리뷰어 내 위험 위치 확인
- 권장 개입 전략 결정

### 리텐션 플레이북

- 위험 유형별 권장 전략 확인
- 개입 전략 선택
- 향후 실행 결과 기록

## 디자인 원칙

- 페이지마다 목적에 맞는 레이아웃을 사용한다.
- 모든 정보를 카드로 감싸지 않는다.
- 핵심 행동과 참고 정보를 시각적으로 구분한다.
- 숫자보다 변화와 의미를 우선적으로 보여준다.
- 장식용 그래프가 아니라 판단에 필요한 시각화를 사용한다.
- 운영 홈에는 전체 상황, Reviewer 360에는 개인의 시간 변화를 강조한다.
- 기본 Streamlit 컴포넌트의 노출을 최소화한다.
- 발표 화면과 실제 운영 화면 모두 자연스럽게 구성한다.

## 현재 구현 불가능한 기능

데이터가 없는 기능은 작동하는 것처럼 만들지 않고
`고도화 예정` 상태로 표시한다.

- 실제 CRM 메시지 발송
- 개입 이력 저장
- 개입 전후 성과 추적
- 실시간 지역 콘텐츠 위험
- 음식점 B2B 리포트

## 관리자 판단 저장 범위 결정 (2026-07-26)

관리자 판단(`reviewer_decisions`)은 운영 홈 큐 필터링과 리뷰어 관리 워크리스트의
검토 완료 집계·배지에 동시에 쓰이는 핵심 상호작용이다. 다만 현재는
`st.session_state`에만 있어 서버 재시작·새 브라우저 세션에서 소실된다
(8501 재기동 시 판단 완료 카운트가 0으로 리셋되는 것을 실제로 확인함).

- **결정**: 새로고침·서버 재시작에도 판단이 남도록 가벼운 로컬 저장(JSON
  또는 SQLite 파일)으로 전환한다. 다중 운영자 동시 편집, 운영자 인증,
  CRM 연동, 감사 로그는 이번 결정에 포함하지 않고 위 "현재 구현 불가능한
  기능"(개입 이력 저장) 범위로 그대로 남긴다.
- **플레이북 연동 보강**: 리뷰어 360의 "플레이북에서 전략 확인" 버튼이
  현재 보고 있는 리뷰어의 `risk_type`을 넘기지 않아, 클릭해도 그 리뷰어와
  무관한 기본/직전 유형이 열린다. 리뷰어 360 리디자인 작업에 포함해 함께
  고친다.
- **상태**: 방향 합의됨. 코드 미반영 — 리뷰어 360 구현 작업에서 반영 예정.
